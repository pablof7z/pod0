<objective>
Close the SC5/HOST-05 regression `01-VERIFICATION.md` found: 01-04's gap-closure fix disabled `create_store`, which as a side effect made `tests/live_agent.rs::headless_turn_completes_after_approved_capability_execution` — the only test that ever proved approval + capability-execution parity end-to-end — `#[ignore]`d and non-runnable. The approval-decision code itself (`host.rs`'s `PresentAgentApproval` arm, unconditionally returning `AgentApprovalDecision::Approve`) is untouched and correct; only the test's fixture setup is broken, because it depends on the now-disabled `Pod0Facade::create`.

The fix is a store fixture that reaches a usable store WITHOUT `Pod0Facade::create`: pre-seed a fresh SQLite file with the four authority markers `Pod0Facade::open` (which DOES exist at committed HEAD) requires — `pod0_domain_cutovers` rows for the `listening`, `notes`, and `transcripts` domains, and an authoritative `pod0_chapter_state` row — using only `pod0-storage`'s already-public `CoreStoreMigrator` plus raw SQL that mirrors patterns already established and passing in `pod0-storage`'s own committed test suite (`agent_store_tests.rs`'s migrate-only fixture, `model_chapter_workflow/success_tests.rs`'s `activate_chapter_authority` helper). Then open that pre-seeded store via the CLI's existing `open_store` command (`Shell::handle` -> `app/store.rs::open_store` -> `Pod0Facade::open`), instead of `create_store`.

Purpose: Restore a real, running, non-ignored automated test for HOST-05's "headless tests exercise real approvals instead of auto-denying" criterion, without touching pod0-facade/pod0-storage (someone else's uncommitted, out-of-scope WIP) and without re-enabling `create_store` (which has no committed backing implementation).
Output: A reusable store-bootstrap test helper in `pod0-cli`'s own test suite, `headless_turn_completes_after_approved_capability_execution` un-ignored and passing, and (best-effort) the same fix applied to as many of the other 11 `#[ignore]`d tests as the same pattern cleanly covers.
</objective>
